# Third-party components

Original baseline code is covered by [LICENSE](LICENSE) and [NOTICE](NOTICE). The license does not cover third-party materials or challenge data.

- **CASCADE devkit**: NVIDIA / nv-tlabs, Apache 2.0, commit `776102861a4fc587c7ca2141647d4562b93b7f15`, tag `release/0.2.1`. Retrieved into `vendor/cascade-devkit`; its LICENSE remains there. The local adapter and scorer import its code, which is not included in the inference build context. Source: https://github.com/nv-tlabs/cascade-devkit.
- **BLIP caption model**: Salesforce, model `Salesforce/blip-image-captioning-base`, revision `82a37760796d32b1411fe092ab5d4e227313294b`. The model card states BSD-3-Clause; the BLIP repository license is preserved in `third_party_licenses/BLIP-LICENSE.txt`. The pinned public weights are converted locally from tensor-only loading to safetensors. Sources: https://huggingface.co/Salesforce/blip-image-captioning-base and https://github.com/salesforce/BLIP.
- **Python runtime dependencies**: PyTorch, Transformers, Pillow, PyYAML, and huggingface-hub, plus transitive dependencies. Direct versions are in `requirements.txt`; the installed Mac environment is recorded in `requirements.local-lock.txt`. Dependencies retain their installed distribution licenses; Linux/CUDA dependencies require separate verification when a container is built.
- **Video tools**: Local `ffmpeg`/`ffprobe`; the container recipe installs the distribution's `ffmpeg` package. Licensing/build options depend on the installed distribution.
- **Development data/storage tools**: `physical-ai-av==0.2.2` and `boto3==1.43.109`, with transitive dependencies, are declared separately in `requirements-data.txt` and `requirements-storage.txt`. Boto3 distribution metadata states Apache-2.0. These SDKs are excluded from the inference build context and retain their installed licenses.

CASCADE and PhysicalAI video data are not included in the build context. External pretrained-model competition eligibility remains an open organizer question. This inventory is not a completed review of a final container's full dependency licenses.

Native retrieval build context (development integration):

- **Qwen3-VL-Embedding-2B**: pinned model revision `9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda`. The recorded model specification declares Apache-2.0. The native context preserves model provenance and every allowlisted asset hash. Model-card source: https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B/tree/9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda.
- **Pinned Qwen embedding helper**: copied unchanged from that revision's `scripts/qwen3_vl_embedding.py`; its SHA-256 is tied to the extraction manifest and package recipe. Source: https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B/blob/9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda/scripts/qwen3_vl_embedding.py. The exact helper implementation matches the official QwenLM source at commit `f4d8d40802a20a9263ab3f99c80b1b2f49852101`, apart from a terminal newline. The same-commit Apache2.0 license is preserved unmodified in `third_party_licenses/Qwen3-VL-Embedding-LICENSE.txt`; pinned sources and scope limits are in `third_party_licenses/Qwen3-VL-Embedding-source.json`. Repository license scope is interpreted normally; no separate file-specific grant is claimed.
- **Qwen3-VL-Embedding-8B finalist**: pinned revision `2c4565515e0f265c6511776e7193b22c0968ddc7`. Its pinned model card declares Apache2.0: https://huggingface.co/Qwen/Qwen3-VL-Embedding-8B/blob/2c4565515e0f265c6511776e7193b22c0968ddc7/README.md. The HF tree has no standalone LICENSE or NOTICE; the included license text comes from the official QwenLM code repository, not a claimed model-revision file. This declaration and provenance do not establish challenge eligibility. Actual model shards are independently checked by the local package manifest.
- **Native Python dependencies**: PyTorch, torchvision, Transformers, qwen-vl-utils, NumPy, safetensors, Pillow and huggingface-hub. Direct pins are in `requirements-native.txt`; the exact built container's resolved versions are in `runs/native-container-readiness-v2/requirements-resolved.txt`, with distribution license metadata and FFmpeg build flags in `dependency-inventory.json` beside it. Installed notices and component eligibility remain to be reviewed. The local-only artifact passed RTX offline reconstruction; this inventory does not establish final eligibility or actual A100 compatibility.
